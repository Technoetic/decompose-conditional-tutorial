# IF / CLEAR

카페의 여름 행사로 배우는 **Decompose Conditional** 인터랙티브 튜토리얼입니다.

**[튜토리얼 열기](https://technoetic.github.io/decompose-conditional-tutorial/)**

복잡한 조건문을 `isSummer`, `summerCharge`, `regularCharge`라는 세 가지 의도로 나눕니다. 조건과 두 갈래 계산에 이름을 붙여도 같은 입력의 결과는 유지돼야 합니다.

## 직접 해 보는 여섯 단계

1. 영수증으로 시작: 같은 주문과 같은 결과.
2. 조건 읽기: 조건·참 분기·거짓 분기를 눌러 구별.
3. 분해 스튜디오: 함수 이름을 선택해 알맞은 역할에 배치.
4. 경계 실험실: 시작일·종료일과 전후 날짜 비교, 명시적인 버그 실험.
5. 여섯 문제와 내 말로 남기는 메모.
6. 독립 실행 가능한 전체 코드와 지킬 원칙.

예시는 **가상 카페의 2026년 요금**입니다. 행사 기간은 6월1일~8월31일 양끝 포함, 잔당4,000원이고 포장비를 포함합니다. 그 밖의 날에는 잔당4,500원과 주문당500원을 계산합니다. 실제 업체의 요금이나 업무 데이터가 아닙니다. 1~12잔, 유효한2026년 날짜만 받습니다.

## 로컬 실행

Node.js22 이상이 필요합니다. 실행 패키지 설치는 없습니다.

```sh
npm test
npm start
```

기본 주소는 http://127.0.0.1:8906/decompose-conditional-tutorial/ 입니다. 다른 포트는 `npm start -- --port 8910`으로 선택할 수 있습니다.

```sh
npm run build
```

`dist/`가 GitHub Pages 배포 산출물입니다. 소스는 화면·서비스·도메인·공통 모듈과 CSS 토큰·기본·컴포넌트로 분리됩니다. 동적 데이터를 제외한 앱 코드에서 배포 식별자와 자산 파일명을 계산합니다. 같은 버전의 학습 내용도 화면 이동 시 새로 요청합니다.

## 저장과 업데이트

답과 메모는 현재 브라우저의 로컬 저장소에만 저장됩니다. 로그인·원격 DB·분석 추적은 없습니다. 저장이 차단되거나 실패하면 입력을 보존하고 오류를 표시합니다.

열린 탭에서 새 배포나 롤백을 발견하면, 입력이 안전한 다음 화면 이동에서 대상 화면을 새 문서로 자동 로드합니다. 미저장 입력과 진행 중인 저장은 보호합니다. GitHub Pages의 캐시 헤더는 플랫폼 정책이며 직접 지정하지 않습니다. 캐시 회피 요청·버전별 자산·검증된 이전 자산 보존을 함께 사용합니다.

## 근거와 범위

- [Martin Fowler — Decompose Conditional](https://refactoring.com/catalog/decomposeConditional.html)
- [Martin Fowler — Extract Function](https://refactoring.com/catalog/extractFunction.html)

예제와 설명은 위 기법을 설명하기 위해 새로 구성했습니다. 리팩토링은 성능 향상을 보장하지 않으며, 실험실의 의도적인 `>=`→`>` 버그는 올바른 리팩토링과 구분합니다. 코드의 값뿐 아니라 관찰 가능한 동작과 평가 순서도 보존해야 합니다.

검증 범위와 미시험 항목은 [검증 기록](docs/verification.md)에 남깁니다. 화면·경계값·동작 보존·오류/저장/배포 전환을 구분합니다.
